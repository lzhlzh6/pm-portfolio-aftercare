Day 6 — 高保真可交互原型

作品集「售后管家 AfterCare」第六天产出。
不是静态图，是能点能跳的真实网页原型。

一、打开方式

双击 原型.html，用浏览器（Chrome / Edge）打开。无需安装任何东西，不联网也能跑。

  1. 点击「登录」进入主应用
  2. 左侧导航切换四个页面
  3. 随便点、随便发消息，都是真的有反应

二、四个页面

1️⃣ 会话工作台（核心页）

三栏布局，这是 B 端客服产品的标准结构：

区域 展示内容
左栏 会话列表：渠道标签、最后一条消息、未读徽章、AI/风险标签
中栏 对话区：客户/AI/客服三种气泡样式区分，AI 回复带置信度与引用来源
右栏 客户信息：基本信息、关联订单、物流轨迹、风险标签

可以试的交互
- 点左侧任一会话 → 对话内容和右侧客户信息同步切换
- 在输入框发消息 → 消息上屏，时间自动取当前时间
- 点底部快捷话术 → 自动填入输入框
- 点「建工单 / 升级主管 / 转接」→ 顶部弹出操作反馈

2️⃣ 工单管理

列表展示 8 条工单，含工单号、类型、客户、渠道、金额、状态、优先级、处理人、创建时间。

状态用彩色标签区分（AI 处理中 / 人工处理中 / 待审批 / 已解决 / 已关闭），优先级高中低三档。

3️⃣ 退款审批（亮点页）

这个页面是整套原型里最值得演示的。

每张待审批卡片下方都有一个黑底的 AI 决策链路（decision_path） 区块，逐行展示退款决策树每一步的判断：

step1_reason        : no_reason_7d              ✓ pass
step1_signed_days   : 3 天（≤7）                ✓ pass
step2_amount        : 1299.00                   ✗ 拦截 / 转人工
step2_threshold     : 200.00（全局默认）        ✗ 拦截 / 转人工
step2_note          : 金额 > 阈值 → 转人工审批   ✗ 拦截 / 转人工
step3_refund_rate   : 0.20（≤0.30）             ✓ pass
step4_sku_blacklist : false                     ✓ pass
final               : pending_approval          ✗ 拦截 / 转人工

这就是 PRD 里 decision_path 字段的可视化。 商家问"这笔为什么没自动退"，指着这个区块就能回答——AI 把理由摆出来了，不是黑盒。

可以点「通过并执行退款」/「驳回」，卡片会切换为结果态：
- 通过 → 绿色提示"退款执行中，1-3 个工作日到账"
- 驳回 → 红色提示"工单回到人工处理中，客户体感仍为同一客服"

4️⃣ 数据看板

  • 4 个 KPI 卡片：AI 拦截率 63.2%、一次解决率 78.6%、平均首响 18 秒、AHT 4.2 分钟（均对照 Day 1 成功指标）
  • 近 7 天双色柱状图（总会话量 vs AI 拦截量）
  • 售后意图分布 TOP 6（横向条形图）

三、原型刻意埋的设计细节

演示时如果能主动指出这些，说明你不是"画了个界面"，而是"想过业务"：

细节 位置 为什么这么设计
AI 回复带置信度与来源 工作台对话区 让客服敢信 AI。没来源的回复，客服不敢直接用
置信度低于 0.85 标橙 王阿姨那条会话 视觉上区分"可放心用"和"需人工复核"
高风险客户红标签 周女士（退款率 42%） 对应 PRD 决策树步骤 3，客服一眼看到风险
决策链路可视化 审批页 打消主管"AI 乱来"顾虑的核心手段
驳回不回客户，回人工 审批驳回提示 保持客户体感连续，这是 B 端最容易忽略的一点
AI 拦截率/一次解决率写真实目标 看板 指标不是装饰，直接挂 Day 1 定的成功标准
未读徽章点击后清零 会话列表 还原真实交互，细节到位

四、三分钟演示脚本

第 1 分钟：工作台

"这是客服每天真正盯的界面。三栏：左边会话列表，中间对话，右边客户信息。
注意 AI 的回复都带置信度和引用来源——这不是装饰，是让客服敢直接用。
置信度低于 0.85 会标橙，提示这条需要人工复核。"

第 2 分钟：切到审批页，讲决策链路

"这是整个原型的核心页面。超阈值的退款会走到这里，下方黑底区块是 AI 的决策链路。
前两步判定通过，第三步金额 1299 超过阈值 200，因此拦截转人工。
AI 不只是给出结论，还把推理过程摆了出来。 商家问'这笔为什么没自动退'，指着这行就能回答。"

第 3 分钟：点一下"驳回"

"注意驳回的文案——'回到人工处理中，客户体感仍为同一客服'。
很多产品做审批流，驳回就把单子打回客户，客户得重新描述一遍问题。这个坑我们特意避开了。"

五、技术实现说明

纯手写 HTML + CSS + JavaScript，零依赖。

  • 无框架、无构建、无外部 CDN 请求
  • 单文件 44 KB，可直接邮件发送或上传任意静态托管
  • 数据以 JS 对象模拟，可快速替换为真实接口
  • 图表为原生 SVG / CSS 绘制，未引入图表库

为什么不用墨刀/Figma 原型？

对比 墨刀/Figma 原型 本 HTML 原型
交互真实度 页面跳转为主 真实 DOM 交互，数据联动
交付形式 需对方装客户端或看链接 单个 HTML 文件，双击即开
放进作品集 只能截图 可挂真实链接，对方能直接打开体验
修改成本 拖拽调整 改数据对象即可
技术说服力 展示设计能力 同时展示产品 + 技术理解

最后一条对技术背景的产品经理尤其重要——能跟开发用同一种语言对话。

六、已知限制

限制 说明
数据为模拟 未接真实后端，数据写死在 JS 对象里
AI 回复为预设 未接真实大模型，按关键词规则模拟
未做响应式 客服工作台定位为桌面端，主管审批页才需移动端适配
异常流未全部覆盖 PRD 第十一章列了 14 个异常场景，原型只演示了主流程

明确原型的边界，本身就是产品素养的一部分。
