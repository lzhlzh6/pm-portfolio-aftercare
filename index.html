这个项目要解决什么

先说清问题，再谈方案

信通院数据显示：尽管智能客服已被广泛部署，但 86% 的项目效果不及预期，具备完整 Agent 自主决策能力的产品 不足 15%。

典型表现：客户问"我的货到哪了"，大部分机器人的反应是回一段物流查询教程，而不是直接调 API 把结果查出来。 会答题和会办事，是两回事。

同时，市场存在明显的价格断层：美洽等低价产品（3-8 万/年）做不了复杂工单，智齿等成熟产品（30-50 万/年）中小企业买不起。 5-15 人客服团队的商家，卡在中间没人管。

四个核心设计

体现产品判断力的部分

🌳

退款 Agent 五步决策树

不是"能自动退"，而是"知道什么时候不该自动退"。质量问题需要人看图判责，AI 不瞎判；金额超阈值必须人工拍板。

三重约束：条件自动 + 金额阈值 + 全程留痕
🔍

决策链路可视化

用 decision_path 字段记录决策树每一步的判断结果，商家问"这笔为什么没自动退"，指着这行就能回答——AI 不是黑盒。

拒绝黑盒 · 逐笔可追溯
🔄

驳回不打回客户

主管驳回后工单回到"人工处理中"，而不是打回客户重新描述。客户体感仍是同一个客服在跟他沟通。

B 端最容易忽略的体验细节
⚖️

AI 自动化边界判断框架

信息可得 / 规则明确 / 动作可执行 / 风险可控——四条全中才敢全自动。这是判断"AI 该不该接管某个场景"的可复用标准。

七天完整产出

每一天的交付物都是成品，不是计划

Day 1 市场与竞品调研 查看文档
市场规模（IDC 285 亿，CAGR 32%+）、8 家竞品逐家拆解、竞品对比表、三个市场空白、产品定位与 5 个可量化成功指标。
关键结论：找到 5-15 人客服团队商家的价格断层
Day 2 用户画像与场景拆解 查看文档
3 个 Persona（老板 / 主管 / 一线客服）、15 个售后场景全量拆解、12 条用户故事、12 条需求启示、AI 能力边界判断框架。
关键结论：B 端用的人和买的人不是同一个人，三方诉求直接打架
Day 3 需求清单与优先级 查看文档
6 大模块 33 条需求，MoSCoW 分级 + 三维度打分，每条带可量化验收标准；版本分期与明确不做清单。
关键决策：金额阈值审批提到 Must（它是 AI 退款的技术前提）
Day 4 流程图 / 状态机 / 权限矩阵 查看图集 设计说明
5 泳道主流程图（含 AI/人工分流与两条回流）、工单状态机（8 状态 + 超期监控）、RBAC 权限矩阵（5 角色 × 12 操作）。
关键设计：把"系统"也作为权限矩阵的一行，明确 AI 边界
Day 5 PRD 产品需求文档 查看文档
14 章覆盖 V1.0 全部 23 条需求。含退款决策树、4 个对象的字段级数据字典、14 个异常场景、11 个埋点事件与指标口径。
关键细节：AI 拦截率分子不含客户主动要求人工的会话（口径歧义显式说明）
Day 6 可交互高保真原型 打开原型 设计说明
4 个页面（工作台 / 工单 / 审批 / 看板），纯手写 HTML+CSS+JS 零依赖，真实 DOM 交互。含 AI 决策链路可视化。
关键优势：真实网页可在线直接体验，比静态截图更有说服力
Day 7 作品集整合与交付
将前六天的产出整合为统一入口，完成文档排版、编码兼容与在线可访问性优化，形成可直接对外展示的完整作品集。
